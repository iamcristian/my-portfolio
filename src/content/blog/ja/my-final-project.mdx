## はじめに

情報・技術セキュリティ大学院ディプロマ課程の最終プロジェクト（同時にシステム工学学士号を取得するためのダブルディグリー卒業要件）として、私は2024年にサン・シモン大学（UMSS）のSISGAAウェブシステムに対し、許可されたペネトレーションテスト（侵入テスト）評価を実施しました。本プロジェクトでは、当時最新であった業界標準フレームワーク **OWASP Top 10:2021** および **OWASP API Security Top 10 (2023)** を適用し、セキュリティ脆弱性の特定、分析、および軽減策の策定を行いました。

> **注:** 本プロジェクトの完全な学術論文は、<a href="http://atlas.umss.edu.bo/handle/123456789/47539" target="_blank" rel="noopener noreferrer">UMSSの機関リポジトリ</a>で閲覧可能です。以下に記載するすべての発見事項は、2024年に管理されたテスト環境下で実施され、改善ガイドラインとともに大学側へ提出された当時の評価記録であり、現在の稼働システムの状態を示すものではありません。

## プロジェクトの背景

SISGAA (Sistema de Gestión Académica y Administrativa) システムは、情報システム学科で使用されているウェブアプリケーションです。学術および管理業務を担っているため、国際的なセキュリティ基準に照らしてその安全性を評価することは、組織のソフトウェア品質を強化する上で重要でした。

## 定義・方法論

構造化されたペネトレーションテストの手法に従い、以下の手順を実施しました：

1. **計画とスコープの定義**: 許可されたセキュリティ評価の対象範囲と目的を明確に設定しました。
2. **情報収集**: システムアーキテクチャおよびテクノロジースタックに関するデータを収集しました。
3. **脆弱性分析**: OWASPの基準に照らして潜在的なセキュリティの弱点を特定しました。
4. **管理下での実証検証**: 制御されたテスト環境により、脆弱性の有無を確認しました。
5. **文書化**: 発見事項と具体的な修正・軽減策を詳細に記録しました。

## 技術的アプローチ

ペネトレーションテストのプロセスでは、2024年時点で最新であった2つのOWASPフレームワークを組み合わせて適用しました：

### ウェブアプリケーションテスト (OWASP Top 10:2021)

**OWASP Top 10:2021** のカテゴリに基づき、以下の項目を中心にテストを実施しました：

- **A03:2021 – インジェクション（クロスサイトスクリプティング / XSS を含む）**
- **A07:2021 – 識別と認証の失敗**
- **A02:2021 – 暗号化の失敗**（機密データの露出）
- **A05:2021 – セキュリティの設定ミス**
- **A06:2021 – 脆弱で古くなったコンポーネント**

### APIセキュリティテスト (OWASP API Security Top 10 – 2023)

現代のウェブアプリケーションはREST APIに強く依存しているため、**OWASP API Security Top 10 (2023)** の手法を併用しました：

1. **ディスカバリ**: APIの構造とエンドポイントの全体像を把握（**API9:2023 – インベントリの不適切な管理**）。
2. **エンドポイント解析**: リクエスト・レスポンスのパターンおよび設定を調査（**API8:2023 – セキュリティの設定ミス**）。
3. **認証テスト**: ログインおよびトークン機構の検証（**API2:2023 – 認証の不備**）。
4. **認可の検証**: オブジェクトレベルおよび機能レベルのアクセス制御境界をテスト（**API1:2023 – オブジェクトレベル認可の不備** および **API5:2023 – 機能レベル認可の不備**）。

## 主な発見（2024年時点の評価結果）

2024年の評価において、改善対象として以下のカテゴリの課題が記録されました：

1. **反射型クロスサイトスクリプティング (OWASP A03:2021)**: 特定パラメータにおける出力エンコーディングの不備。
2. **オブジェクトレベル認可の不備 (OWASP API1:2023)**: 一部のAPIエンドポイントにおけるリソース所有権チェックの不足。
3. **機能レベル認可の不備 (OWASP API5:2023)**: 管理系エンドポイントにおけるロール検証の不足。
4. **APIドキュメントの公開設定 (OWASP API8:2023 / API9:2023)**: Swaggerによるエンドポイント仕様への公開アクセス。
5. **HTTPセキュリティヘッダーの欠落 (OWASP A05:2021)**: `Content-Security-Policy` や `X-Frame-Options` などのブラウザ保護ヘッダーの未設定。
6. **古いJavaScriptライブラリの使用 (OWASP A06:2021)**: 既知の脆弱性報告があるフロントエンド依存ライブラリの使用。

## 技術的実装（使用ツール）

本プロジェクトでは、以下の専門的なセキュリティツールを活用しました：

- **OWASP ZAP**: 自動化された脆弱性スキャンの実施。
- **Burp Suite**: HTTPリクエストの傍受と分析。
- **カスタムスクリプト**: API認可の境界をテストするための検証スクリプト。
- **ブラウザ開発者ツール**: クライアントサイドの挙動解析。

## 影響と軽減策

2024年の報告書で記録された各項目に対して、具体的な修正・軽減策を提案しました：

- **入力値の検証と文脈に応じた出力エンコーディング**: XSSおよびインジェクション攻撃を防止する。
- **きめ細かな認可チェックの実装**: すべてのAPIルートでオブジェクトおよびロール単位のアクセス制御を強制する。
- **API公開面のハードニング**: インタラクティブな仕様ドキュメントを開発環境のみに制限する。
- **セキュリティヘッダーの実装**: ブラウザベースの多層防御ポリシーを強化する。
- **依存ライブラリのライフサイクル管理**: サードパーティ製コンポーネントの継続的な監査と更新を行う。

## おわりに

本プロジェクトにより、**OWASP Top 10:2021** および **OWASP API Security Top 10 (2023)** に基づく体系的なペネトレーションテストが、アーキテクチャや設定上の弱点を早期に洗い出し、確実な修正へとつなげる上で有効であることが示されました。また、ソフトウェア開発ライフサイクル全体にわたってセキュリティ対策を組み込むことの重要性を改めて確認する機会となりました。

## 実証された技術スキル

- ウェブアプリケーションに対するセキュリティ評価 (OWASP Top 10:2021)
- APIセキュリティテスト (OWASP API Security Top 10 – 2023)
- 管理された環境での脆弱性検証技術
- セキュリティ文書の作成および改善レポーティング
- OWASP手法の実践的応用
