## Введение

В качестве итоговой работы последипломной программы по информационной и технологической безопасности — которая одновременно служила квалификационным проектом по программе двойного диплома (_doble titulación_) для получения степени бакалавра наук в области системной инженерии — в 2024 году я провел авторизованную оценку безопасности (тестирование на проникновение) веб-системы SISGAA в Университете Майор де Сан-Симон (UMSS). В проекте применялись актуальные на тот момент редакции стандартов **OWASP Top 10:2021** и **OWASP API Security Top 10 (2023)** для выявления, анализа и разработки рекомендаций по устранению уязвимостей.

> **Примечание:** Ознакомиться с полным академическим документом данного проекта можно в <a href="http://atlas.umss.edu.bo/handle/123456789/47539" target="_blank" rel="noopener noreferrer">институциональном репозитории UMSS</a>. Все описанные ниже результаты отражают срез академической оценки безопасности, проведенной в 2024 году в контролируемой среде и переданной университету вместе с рекомендациями по устранению; они не описывают текущее состояние какой-либо рабочей системы.

## Предпосылки проекта

Система SISGAA (Sistema de Gestión Académica y Administrativa) — это веб-приложение, используемое Департаментом информатики и систем. Поскольку она обслуживает академические и административные процессы, проверка её защищенности по международным стандартам имела важное значение для повышения надежности университетского программного обеспечения.

## Методология

В своей работе я придерживался структурированной методологии тестирования на проникновение:

1. **Планирование и определение области действия**: Установка четких границ и целей для авторизованной оценки безопасности.
2. **Сбор информации**: Сбор данных об архитектуре системы и технологическом стеке.
3. **Анализ уязвимостей**: Выявление потенциальных слабых мест по критериям OWASP.
4. **Контролируемая проверка**: Подтверждение уязвимостей посредством контролируемого тестирования.
5. **Документирование**: Подробное описание результатов и рекомендаций по устранению для команды разработчиков.

## Технический подход

Процесс тестирования на проникновение опирался на две актуальные в 2024 году редакции стандартов OWASP:

### Тестирование веб-приложений (OWASP Top 10:2021)

Я провел тестирование в соответствии с категориями **OWASP Top 10:2021**, включая:

- **A03:2021 – Инъекции (включая межсайтовый скриптинг / XSS)**
- **A07:2021 – Ошибки идентификации и аутентификации**
- **A02:2021 – Криптографические сбои** (раскрытие конфиденциальных данных)
- **A05:2021 – Небезопасная конфигурация**
- **A06:2021 – Уязвимые и устаревшие компоненты**

### Тестирование безопасности API (OWASP API Security Top 10 – 2023)

Поскольку современные веб-приложения тесно интегрированы с REST API, я дополнил аудит методологией **OWASP API Security Top 10 (2023)**:

1. **Обнаружение**: Составление схемы структуры API и его конечных точек (**API9:2023 – Ненадлежащее управление инвентаризацией**).
2. **Анализ конечных точек**: Изучение паттернов запросов, ответов и конфигураций (**API8:2023 – Небезопасная конфигурация**).
3. **Тестирование аутентификации**: Проверка механизмов входа и управления сессиями (**API2:2023 – Нарушенная аутентификация**).
4. **Проверка авторизации**: Тестирование границ контроля доступа на уровне объектов и функций (**API1:2023 – Нарушенная авторизация на уровне объектов** и **API5:2023 – Нарушенная авторизация на уровне функций**).

## Ключевые результаты (оценка по состоянию на 2024 год)

В ходе проверки 2024 года были задокументированы следующие категории уязвимостей для последующего устранения:

1. **Отраженный межсайтовый скриптинг (OWASP A03:2021)**: Недостаточное экранирование вывода в отдельных параметрах при контролируемых проверках.
2. **Нарушение авторизации на уровне объектов (OWASP API1:2023)**: Отсутствие проверки принадлежности ресурса в ряде конечных точек API.
3. **Нарушение авторизации на уровне функций (OWASP API5:2023)**: Недостаточная проверка ролей при обращении к привилегированным маршрутам.
4. **Раскрытие документации API (OWASP API8:2023 / API9:2023)**: Публичный доступ к спецификациям конечных точек через Swagger.
5. **Отсутствие заголовков безопасности HTTP (OWASP A05:2021)**: Отсутствие защитных заголовков браузера, таких как `Content-Security-Policy` и `X-Frame-Options`.
6. **Устаревшие JavaScript-библиотеки (OWASP A06:2021)**: Использование клиентских компонентов с известными уязвимостями.

## Техническая реализация

В проекте использовались специализированные инструменты безопасности:

- **OWASP ZAP**: Для автоматизированного сканирования уязвимостей.
- **Burp Suite**: Для перехвата и анализа HTTP-запросов.
- **Пользовательские скрипты**: Для проверки границ авторизации API.
- **Инструменты разработчика браузера**: Для анализа клиентского поведения веб-приложения.

## Последствия и смягчение рисков

Для каждого выявленного в отчете 2024 года несоответствия я подготовил конкретные стратегии устранения:

- **Валидация ввода и контекстное кодирование вывода**: Для предотвращения XSS и инъекций.
- **Детальная проверка авторизации**: Для принудительного контроля доступа на уровне объектов и ролей в каждом маршруте API.
- **Защита поверхности API**: Для ограничения доступа к интерактивной документации вне сред разработки.
- **Реализация заголовков безопасности**: Для усиления эшелонированной защиты на уровне браузера.
- **Управление зависимостями**: Для регулярного аудита и обновления сторонних библиотек.

## Заключение

Этот проект продемонстрировал, как систематическое тестирование на проникновение на основе **OWASP Top 10:2021** и **OWASP API Security Top 10 (2023)** позволяет своевременно выявлять архитектурные и конфигурационные недостатки для их планомерного устранения. Результаты подчеркнули важность интеграции практик безопасной разработки на всех этапах жизненного цикла ПО.
