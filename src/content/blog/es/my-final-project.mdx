## Introducción

Como trabajo final del Diplomado en Seguridad de Tecnologías e Información —el cual sirvió simultáneamente como modalidad de doble titulación para obtener mi Licenciatura en Ingeniería de Sistemas—, realicé en 2024 una evaluación autorizada mediante pruebas de penetración al sistema web SISGAA de la Universidad Mayor de San Simón (UMSS). El proyecto aplicó las ediciones vigentes en ese año de los estándares **OWASP Top 10:2021** y **OWASP API Security Top 10 (2023)** para identificar, analizar y documentar recomendaciones de mitigación ante vulnerabilidades de seguridad.

> **Nota:** Puedes consultar la monografía académica completa en el <a href="http://atlas.umss.edu.bo/handle/123456789/47539" target="_blank" rel="noopener noreferrer">repositorio institucional de la UMSS</a>. Los hallazgos descritos a continuación corresponden a una evaluación académica puntual realizada en 2024 en un entorno controlado y entregada a la institución junto con su guía de remediación; no representan el estado actual de ningún sistema en producción.

## Antecedentes del Proyecto

El sistema SISGAA (Sistema de Gestión Académica y Administrativa) es una aplicación web utilizada por el Departamento de Informática y Sistemas. Dado que gestiona procesos académicos y administrativos, evaluar su postura de seguridad bajo estándares internacionales resultaba fundamental para fortalecer la calidad del software institucional.

## Metodología

Mi enfoque siguió una metodología estructurada para pruebas de penetración:

1. **Planificación y Definición del Alcance**: Establecimiento de límites y objetivos claros para la evaluación autorizada.
2. **Recopilación de Información**: Recolección de datos sobre la arquitectura del sistema y su base tecnológica.
3. **Análisis de Vulnerabilidades**: Identificación de posibles debilidades frente a los marcos de referencia OWASP.
4. **Explotación Controlada**: Verificación técnica de los hallazgos mediante pruebas controladas.
5. **Documentación**: Elaboración de reportes detallados y guías de mitigación para el equipo técnico.

## Enfoque Técnico

El proceso de pruebas de penetración incorporó las dos versiones más recientes de los marcos OWASP vigentes en 2024:

### Pruebas de Aplicaciones Web (OWASP Top 10:2021)

Realicé pruebas alineadas con las categorías de **OWASP Top 10:2021**, abarcando:

- **A03:2021 – Inyección (incluyendo Cross-Site Scripting / XSS)**
- **A07:2021 – Fallas de Identificación y Autenticación**
- **A02:2021 – Fallas Criptográficas** (exposición de datos sensibles)
- **A05:2021 – Configuración de Seguridad Incorrecta**
- **A06:2021 – Componentes Vulnerables y Desactualizados**

### Pruebas de Seguridad en APIs (OWASP API Security Top 10 – 2023)

Dado que las aplicaciones web modernas dependen en gran medida de APIs REST, complementé el análisis con la edición **OWASP API Security Top 10 (2023)**:

1. **Descubrimiento**: Mapeo de la estructura de la API y sus endpoints (**API9:2023 – Gestión Inadecuada del Inventario**).
2. **Análisis de Endpoints**: Examen de patrones en peticiones, respuestas y configuraciones (**API8:2023 – Configuración de Seguridad Incorrecta**).
3. **Pruebas de Autenticación**: Verificación de mecanismos de ingreso y sesiones (**API2:2023 – Autenticación Rota**).
4. **Verificación de Autorización**: Pruebas de los límites del control de acceso a nivel de objetos y funciones (**API1:2023 – Autorización Rota a Nivel de Objeto** y **API5:2023 – Autorización Rota a Nivel de Función**).

## Hallazgos Clave (Evaluación Puntual de 2024)

Durante la evaluación de 2024 se documentaron las siguientes categorías de debilidades para su respectiva remediación:

1. **Cross-Site Scripting Reflejado (OWASP A03:2021)**: Codificación insuficiente de salidas en parámetros específicos bajo pruebas controladas.
2. **Autorización Rota a Nivel de Objetos (OWASP API1:2023)**: Ausencia de validación de pertenencia sobre recursos específicos en determinados endpoints.
3. **Autorización Rota a Nivel de Funciones (OWASP API5:2023)**: Verificación insuficiente de roles en rutas administrativas.
4. **Exposición de Documentación de API (OWASP API8:2023 / API9:2023)**: Acceso público a especificaciones interactivas de Swagger.
5. **Falta de Cabeceras HTTP de Seguridad (OWASP A05:2021)**: Ausencia de cabeceras restrictivas en el navegador como `Content-Security-Policy` y `X-Frame-Options`.
6. **Librerías JavaScript Desactualizadas (OWASP A06:2021)**: Uso de dependencias frontend con vulnerabilidades reportadas públicamente.

## Implementación Técnica

El proyecto utilizó herramientas especializadas de seguridad:

- **OWASP ZAP**: Para escaneo automatizado de vulnerabilidades.
- **Burp Suite**: Para interceptar y analizar solicitudes HTTP.
- **Scripts Personalizados**: Para verificar límites de autorización en la API.
- **Herramientas de Desarrollo del Navegador**: Para analizar el comportamiento del cliente web.

## Impacto y Mitigación

Para cada hallazgo documentado en el informe de 2024, propuse estrategias concretas de remediación:

- **Validación de Entradas y Codificación Contextual de Salidas**: Para prevenir vectores XSS e inyección.
- **Controles Granulares de Autorización**: Para hacer cumplir el control de acceso por objeto y rol en cada endpoint.
- **Endurecimiento de la Superficie de API**: Para restringir la documentación interactiva a entornos de desarrollo.
- **Implementación de Cabeceras de Seguridad**: Para reforzar las políticas de defensa en profundidad del navegador.
- **Gestión del Ciclo de Vida de Dependencias**: Para auditar y actualizar componentes de terceros de forma continua.

## Conclusión

Este proyecto demostró cómo las pruebas de penetración sistemáticas basadas en **OWASP Top 10:2021** y **OWASP API Security Top 10 (2023)** permiten identificar debilidades arquitectónicas y de configuración para su oportuna corrección. Los resultados reafirmaron la importancia de integrar prácticas de seguridad a lo largo de todo el ciclo de vida del desarrollo de software.
